# Old dotfiles cleanup and reinstall

This plan applies to the inventoried leftovers on this machine, not the whole home directory or repository. Keep the existing recovery backup unchanged. Do not delete credentials, SSH/GPG keys, password stores, Midway certificates, unrelated tools, or project-required Python versions.

1. **Record and back up the live configuration.** Create a separate, timestamped recovery directory with owner-only permissions. Copy `~/.config/mise/config.toml` and `~/.gitconfig` with their permissions intact. Record each affected symlink's original destination and copy its actual resolved target, including the current Zsh, Neovim and Herdr configuration targets, before replacing anything. Keep a path-to-backup manifest so restoration does not depend on memory. Keep credential contents out of terminal output and logs.

2. **Preserve application state.** Leave Neovim undo files, history, data and Mason state in place, including any custom locations configured by the current editor. Leave Herdr sessions in place. Preserve repository-local Git identities and credential helpers, SSH/GPG configuration, password stores and corporate authentication. The configuration backup is not permission to clear these directories.

3. **Confirm the obsolete assets have no users.** Check live configuration callers and processes before retiring `~/.oh-my-zsh` and `~/.tmux/plugins`. The inventory found stock Oh My Zsh examples and old TPM/gruvbox/sensible plugins; it found no active tmux process. Recheck before relocation. If an asset still has a caller or active process, preserve it until that dependency is retired safely.

4. **Quarantine confirmed leftovers.** Move confirmed obsolete `~/.oh-my-zsh` and `~/.tmux/plugins` into the new recovery directory and record their original locations. Do not use a broad `rm -rf`, wipe the home directory, remove the repository, or touch the old recovery backup. Unlink an obsolete dotfile symlink only when its recorded target proves that this dotfiles checkout owns it; leave unrelated links and regular files alone. `~/.tmux.conf`, `~/.local/scripts` and `~/.zsh-completions` were already missing, so they need no removal.

5. **Retire legacy mise configuration without deleting project tools.** Relocate the backed-up regular `~/.config/mise/config.toml` into recovery before native deployment. Remove only the obsolete `dotnet`, `node`, `poetry` and `tmux` plugin registrations; preserve unrelated tool binaries and Python versions required by projects. Do not run global pruning or an uninstall operation that also removes required runtimes. Native mise deployment must refuse remaining destination conflicts: inspect and back up each conflict rather than enabling bootstrap force or overwriting it.
- If an old standalone `cargo install tree-sitter-cli` shadows the pinned mise parser, back up its executable and Cargo ownership metadata, then retire only that package with `cargo uninstall tree-sitter-cli`.
- Preserve Mason state by default. If a specific installed tool has a stale interpreter path, quarantine only that package and its link, rerun `editor-setup`, and prove the tool's actual behavior before declaring the cutover complete.

6. **Run the live installer once from the checkout.** Run `./init` after the safe cleanup. Its display must identify the current stage, list the tools/packages being installed, retain native per-tool results, and show an honest completed-stage progress bar rather than simulated elapsed-time percentages. A failure must identify its exact stage and retain the original exit code. Do not continue past a failed stage as though installation succeeded.

7. **Check the installed result.** On this AL2 host, run `mise -E al2 dot status --missing` and `mise -E al2 run check`; on other profiles, use the corresponding native `mise dot status --missing` and `mise run check` commands. Inspect deployment status and script links. Confirm that the dotfile-managed links in `~/.local/bin` point to exactly the two repository-declared user helpers, and that the shell resolves them; leave unrelated executables alone. Check the effective global Git email and a personal repository's local email without changing its identity or credential settings. Confirm the editor starts with the deployed configuration, locked plugins and installed tools, and that existing undo/history/Mason state and Herdr sessions remain available. Record actual outcomes rather than reporting an unrun check as passed.

## Recovery

If installation fails, keep the quarantine and both recovery backups. Preview `mise dot unapply --dry-run` (add `-E al2` on AL2) before removing newly managed deployment. Restore files, symlink destinations and quarantined directories from the manifest only after confirming their destinations will not overwrite newer user changes. Restore the previous regular mise config and Git config when reverting the cutover. Do not restore or delete unrelated home-directory state.
